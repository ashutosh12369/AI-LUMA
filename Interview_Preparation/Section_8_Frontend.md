# Section 8 — Frontend (136–155)

**136. Why React?**
React is a powerful, component-based library that allows for building highly interactive UIs. Its Virtual DOM provides excellent performance, and its massive ecosystem makes integrating tools like Redux Toolkit and Tailwind CSS seamless. It's the industry standard for complex applications like AI-LUMA.

**137. Explain your frontend architecture.**
The frontend is built with React, bootstrapped via Vite for lightning-fast HMR and optimized builds. State management is handled by Redux Toolkit for global state (user auth, global settings). Styling is done via Tailwind CSS for rapid, utility-first UI development. Network requests are managed by Axios, which features a custom interceptor to handle 502 Bad Gateway errors automatically (often caused by Render cold starts).

**138. What is the Claude-style artifacts panel?**
The Claude-style artifacts panel is a dedicated UI section that displays complex, structured, or multi-step content generated by the AI separately from the conversational chat thread. For example, if the AI generates code, a CSV table, or an SVG, it renders in this side panel, allowing the user to interact with or copy the artifact without cluttering the chat history.

**139. How is chat UI implemented?**
The chat UI consists of a scrollable message list component and a sticky input area at the bottom. Messages are differentiated by sender (User vs. AI) using distinct styling (Tailwind classes). The UI needs to handle dynamic height adjustments and auto-scrolling to the latest message as new content arrives.

**140. How are streaming responses handled?**
Streaming responses from the AI Agent service are processed using the Fetch API or EventSource for Server-Sent Events (SSE). As chunks of data arrive from the backend, the local component state containing the current AI message is continuously appended with the new text. This state update triggers a re-render, giving the user a real-time typing effect.

**141. How do you manage state?**
We use a hybrid approach. Global state (authentication status, user preferences, billing credits) is managed by Redux Toolkit. Local state (form inputs, currently streaming message chunks, toggle states) is managed using React's `useState` and `useReducer` hooks to avoid unnecessary global re-renders.

**142. How do you handle API errors?**
API errors are caught using `try-catch` blocks or Promise `.catch()` handlers. We employ a centralized Axios interceptor to catch specific errors globally. Notably, an interceptor is configured to automatically retry requests when receiving a 502 Bad Gateway error, which elegantly handles Render's cold start latency without breaking the user experience.

**143. How do you upload files?**
File uploads (e.g., PDFs for RAG, Images for Vision) are handled using an HTML `<input type="file">`. The files are appended to a `FormData` object and sent via an Axios POST request with the `Content-Type: multipart/form-data` header to the backend, which processes them and stores them appropriately.

**144. How is authentication handled?**
Authentication involves sending user credentials to the Gateway, which routes to the Auth microservice. The service returns a JWT upon success. This token is stored securely (typically in an HttpOnly cookie or Memory/Session Storage depending on exact risk profiling) and attached to the Authorization header of subsequent Axios requests via an interceptor.

**145. Why Firebase Authentication?**
*(Note: If Firebase Auth is utilized by the Auth microservice or frontend as an OAuth provider)* Firebase Authentication provides a robust, pre-built solution for handling social logins (Google, GitHub) and email/password management. It offloads the security burden of credential storage and provides standard OIDC tokens that our custom Auth microservice can verify.

**146. How do protected routes work?**
Protected routes are implemented using a Higher-Order Component (HOC) or a wrapper component (like a `<ProtectedRoute>` in React Router). This component checks the Redux store for a valid authentication state. If authenticated, it renders the child components; if not, it redirects the user to the login page using `Navigate`.

**147. How do you manage sessions?**
Sessions are fundamentally managed via the validity of the JWT. The frontend relies on the presence of a non-expired token. If a request returns a 401 Unauthorized (caught by the Axios interceptor), the frontend clears the user state from Redux and redirects to the login screen, effectively terminating the session.

**148. How do you optimize rendering?**
Rendering is optimized by keeping component state as localized as possible, using `React.memo` for components that receive the same props frequently but shouldn't re-render, and utilizing `useMemo` and `useCallback` for expensive calculations and function references to prevent unnecessary child re-renders.

**149. How do you avoid unnecessary re-renders?**
Aside from `React.memo`, we ensure our Redux selectors are specific. Instead of subscribing a component to the entire user object (`useSelector(state => state.user)`), we subscribe only to the necessary primitive (`useSelector(state => state.user.credits)`). This ensures the component only re-renders when the specific property changes.

**150. How do you organize components?**
Components are organized functionally. Common structural components (Buttons, Modals, Inputs) are in a `components/common` folder. Feature-specific components are grouped together (e.g., `features/chat/ChatWindow.jsx`, `features/artifacts/ArtifactPanel.jsx`). Layout components define the overall page structure.

**151. How do you make the UI responsive?**
Tailwind CSS makes responsiveness straightforward. We use mobile-first utility classes and breakpoints (e.g., `md:`, `lg:`) to adjust layouts. For instance, the artifacts panel might be a modal on mobile (`block md:hidden`) but a side-by-side flex container on desktop (`hidden md:flex`).

**152. How do you handle loading states?**
Loading states are managed using boolean state variables (e.g., `isLoading`). When true, the UI renders skeletons, spinners, or pulsing animations (easily implemented with Tailwind's `animate-pulse`). This provides immediate feedback to the user while network requests are pending.

**153. How do you handle dark mode?**
Dark mode is implemented using Tailwind's `dark:` variant mechanism. The user's preference is stored in localStorage and Redux. We toggle a `dark` class on the root `<html>` element based on this state, which automatically applies all `dark:` styled utilities across the application.

**154. How do you improve user experience?**
UX is improved by the 502 auto-retry interceptor hiding server cold starts, streaming LLM text for immediate perceived performance, preserving chat history, using clear loading indicators, and providing a clean, responsive UI with the separated artifacts panel for complex data.

**155. What frontend optimizations did you implement?**
Key optimizations include:
1. **Vite**: Faster dev server and optimized production rollup builds.
2. **Axios Retry**: Interceptor for resilient network requests against cold starts.
3. **State Colocation**: Keeping state close to where it's used.
4. **Code Splitting**: Using React's `lazy` and `Suspense` for route-level code splitting to reduce the initial bundle size.
